Voxa Chatbot

A source-grounded guide to a Python customer-support chatbot prototype. Streamlit accepts typed or host-recorded speech, Flask generates a response with a fine-tuned FLAN-T5 model, and the notebook records the training/export workflow.

Verified from source3 project-owned filesIntermediate interview depthArtifact mismatch documented

Voxa is a compact proof-of-concept named “Voxa - Your AI Customer Support Assistant” in the UI. The supplied repository contains only its Streamlit interface, Flask inference service, and model-training notebook. No README, requirements file, model artifact, database, tests, or deployment configuration is present.

30-second pitch

Voxa lets a user ask a customer-support question by text or a fixed voice recording, sends the text to a local Flask API, displays a model-generated reply, and requests host-side text-to-speech playback.

Objective

Convert a customer query into a concise generated answer through a fine-tuned sequence-to-sequence model, with optional speech input and output.

Target user

A local prototype user seeking a support-style answer. The code does not identify a product domain, authenticated customer group, or organization.

1, 3, and 5 minute explanations

1 minute

Streamlit is the UI, Flask exposes one POST endpoint, and Hugging Face Transformers/PyTorch run a FLAN-T5 model. The notebook prepares customer-support data and fine-tunes the base model.

3 minutes

Input comes from a text field or Whisper transcription of PyAudio WAV audio. The frontend stores only current input/error in session state, calls localhost, renders the answer, then gTTS/pygame plays on the Streamlit host.

5 minutes

The notebook loads 26,872 rows, creates an 80:20 split, trains two epochs, saves voxa_model_cpu, zips it, and copies it to Drive. Flask expects model3, which is absent, so the delivered app cannot load as-is.

Notebook preprocessing excerpt
def preprocess(example):
    input_text = "Answer the customer query: " + example["instruction"]
    target_text = example["response"]
    inputs = tokenizer(input_text, max_length=128, padding="max_length", truncation=True)
    targets = tokenizer(target_text, max_length=128, padding="max_length", truncation=True)
    inputs["labels"] = targets["input_ids"]
    return inputs

Verified caveats

  • Labels are raw padded target IDs; no visible -100 mask means padding may affect loss.
  • The comment says no gradient accumulation, but config sets 4.
  • Training and inference prompt prefixes differ.
  • No global training seed, data revision, or package versions are recorded.

Deep viva answers

  • Why eval mode? Disable training-only behavior such as dropout during inference.
  • Why top-p and top-k? They constrain sampling candidate tokens differently.
  • Why metric output matters? A split alone cannot prove answer quality.
  • Why mask padding? Padding should usually not contribute to token loss.

The backend is one Flask module. Tokenizer/model load during module import and are placed on CUDA when available, otherwise CPU. There are no blueprints, controllers, service classes, middleware modules, or health routes.

backend.py request-to-response excerpt
@app.route("/chat", methods=["POST"])
def chat():
    user_input = request.json.get("message", "")
    prompt = "You are a helpful and friendly customer support assistant. " + user_input
    inputs = tokenizer(prompt, return_tensors="pt").to(device)
    outputs = model.generate(inputs.input_ids, max_new_tokens=128, do_sample=True,
                             temperature=0.7, top_k=50, top_p=0.9)
    response = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return jsonify({"response": response})

A click calls Flask, renders result, labels a whitespace-word count as “Token count,” then runs gTTS/pygame.

Tell me about your project.Voxa is a local customer-support chatbot prototype. Streamlit handles typed/host-recorded voice input, Flask runs model inference, and a notebook fine-tunes FLAN-T5. The key engineering improvement I identified is aligning training export with runtime artifact loading.
